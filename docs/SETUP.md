# خطوات الإعداد — اللي محتاج صلاحياتك إنت

الكود كله جاهز على فرع `dev`. الخطوات دي محتاجة كونسول Firebase وhPanel، ومقدرش أوصلهم من مكاني — الاتنين محجوبين عني. كل خطوة هنا **إنت اللي بتنفذها**.

الموقع الحي والـDNS و`CNAME` ومشروع Elwaset القديم **مش هيتلمسوا** في أي خطوة من دول.

## اللي فاضل عليك دلوقتي — تلات حاجات وبس

| # | الحاجة | فين | ليه |
|---|---|---|---|
| **١** | **انشر `firestore.rules` من جديد** | Firestore → Rules → الصق الملف → Publish | القواعد اتشدّت: بقت بتحصرك إنت كمان في المراجعة بس، ومبتخليكش تعيد كتابة كلام حد أو ترقّي حساب |
| ٢ | فهرس `status` تصاعدي + `createdAt` تنازلي على `reviews` | Firestore → Indexes | **اختياري.** من غيره الترتيب بيتعمل في المتصفح والصفحة شغالة عادي |
| ٣ | `elawaady-db.com` في Authorized domains | Authentication → Settings | الدخول بجوجل بس. الإيميل/الباسورد شغال من غيرها |

اللي خلاص اتعمل: Authentication، Firestore، Owner UID، فهرس
(`uid` + `createdAt`)، وCloudinary.

## تعاملات سابقة — `app.html`

كل الرحلة في ملف واحد: `app.html`.

```
دخول / تسجيل → حسابي → أضف تقييمك → تمويه الصور → pending
                                                              ↓
                                لوحة التحكم (إنت بس) → اعتماد
                                                              ↓
                                            تعاملات سابقة — للعامة
```

### المسارات

| الصفحة | الرابط |
|---|---|
| لوحة التحكم | `app.html#/admin` |
| حساب المستخدم | `app.html#/account` |
| أضف تقييمك | `app.html#/new` |
| تعاملات سابقة | `app.html#/proofs` |

**لوحة واحدة بس.** `admin.html` القديمة بقت تحويلة، وملفاتها
(`admin.js` و`admin-auth.js` و`admin-gate.js` و`admin-config.js`) اتشالت.
`#/links` بقى قسم جوّه اللوحة، والمسار القديم بيحوّل عليه.

**الصفحات جوّه الملف:**

| المسار | مين يشوفها | بتعمل إيه |
|---|---|---|
| `#/proofs` | الكل | تعاملات سابقة — المعتمد بس |
| `#/channels` | الكل | القنوات والمجتمعات — 46 رابط |
| `#/new` | المسجّلين | نموذج التقييم: نجوم + عنوان + نص + نوع تعامل + صور |
| `#/account` | المسجّلين | الاسم والصورة والنبذة وتقييماتك وحالة كل واحد |
| `#/admin` | المالك بس | اللوحة كلها — التقييمات والمستخدمين والروابط والمحتوى والإعدادات |
| `#/links` | المالك بس | تحويلة على `#/admin?s=links` |

**أقسام اللوحة** — `#/admin?s=<القسم>`:

| القسم | بيعمل إيه |
|---|---|
| `reviews` | مراجعة التقييمات: الاسم · الإيميل · النجوم · العنوان · النص · نوع التعامل · الصور · تاريخ الإرسال · الحالة — وأزرار اعتماد · رفض · إخفاء · تثبيت · حذف |
| `users` | الحسابات، إيقاف وتفعيل، وحذف الحساب وتقييماته |
| `links` | إضافة وتعديل وترتيب وإخفاء الروابط |
| `content` | نصوص الصفحة الرئيسية — بتتخزن في `content/portfolio` |
| `images` | صور الموقع — صورتك و«تعاملات سابقة» واللوجو. بترفع على Cloudinary والرابط بيتخزن في نفس المستند |
| `settings` | بيانات التواصل، وقفل/فتح استقبال التقييمات |

`#/reviews` و`#/transactions` بيوصّلوا لنفس صفحة `#/proofs`، عشان أي رابط
قديم يفضل شغال.

**أنواع التعامل:** وساطة · ضمان · بيع وشراء · خدمات رقمية · تحويلات أو
معاملات رقمية · تعاون · استشارة · أخرى.

القائمة دي مكتوبة في مكانين لازم يفضلوا متطابقين: `DEAL_TYPES` في
`app.html`، وقائمة `dealType` في `firestore.rules`. لو زوّدت نوع في واحد
من غير التاني، القاعدة هترفض التقييم.

**حدود الملفات:**

| النوع | الامتدادات | الحد |
|---|---|---|
| صور | JPEG / PNG / WEBP | 4 صور، 5 ميجا للصورة (وبتتضغط قبل الرفع) |

**مفيش فيديو.** التقييم صور إثبات وبس: نجوم، عنوان، نص، نوع تعامل، صور.

**الصور بتترفع على Cloudinary مش على Firebase Storage**، لأن Storage محتاج
خطة Blaze. اللي بيترفع هو ناتج أداة التمويه بعد ما اتصغّر واتضغط، والأصل
مبيخرجش من جهاز المستخدم. اللي بيتخزن في Firestore لكل صورة:
`url, publicId, mime, bytes, uid, reviewId, createdAt` — ولا حقل زيادة،
والقواعد هي اللي بتفرض ده.

**الروابط — مين المرجع؟**

| الحالة | الـSource of Truth | `links.js` بيعمل إيه |
|---|---|---|
| قبل تشغيل Firebase | `links.js` | هو القائمة نفسها |
| بعد التشغيل والمجموعة لسه فاضية | `links.js` مؤقتًا | نسخة زرع، والصفحة بتنبّهك |
| بعد الزرع | **Firestore** (`links`) | نسخة طوارئ وبس |

الزرع بيحصل مرة واحدة: افتح `#/admin?s=links` واضغط الزرار اللي هيكون مكتوب عليه
«ازرع القائمة في Firestore». بعدها التعديل كله من الداشبورد، وتعديل
`links.js` نفسه مش هيبان.

الملف بيشتغل على وضعين، وبيختار لوحده:

| الحالة | الوضع | البيانات |
|---|---|---|
| `firebase-config.js` فاضي | **اختبار** | في المتصفح (IndexedDB) |
| `firebase-config.js` متملّي | **حقيقي** | Firestore (والصور على Cloudinary) |

الوضع التجريبي شغال دلوقتي عشان تجرّب الرحلة كلها. بس **الـconfig لوحده
مش كفاية للإطلاق** — فيه Checklist تحت لازم يعدّي كله الأول.

**حسابات الوضع التجريبي:**

```
عميل         tester@elawaady-db.com   /  Test#2026
صاحب الموقع  owner@elawaady-db.com    /  Owner#2026
```

الحسابات دي موجودة في **الوضع التجريبي بس**. لما تحط الـconfig الحقيقي
بتختفي تمامًا، والدخول بيبقى من فايربيز.

### نسخة المعاينة

```bash
node scripts/build-preview.mjs     # -> preview/reviews-preview.html
```

بتحط الخط واللوجو جوّه ملف واحد يتفتح من غير سيرفر. الكود نفسه مش بيتغير.

## المرحلة الأولى — Firebase (١٥ دقيقة)

### ١. اعمل المشروع

[console.firebase.google.com](https://console.firebase.google.com) → **Add project**

- الاسم: **`elawaady-portfolio`**
- Google Analytics: مش محتاجها — **Disable**

> مشروع جديد ومنفصل تمامًا. مش هنلمس `elwaset-store` ولا ننقل منه أي بيانات.

### ٢. فعّل الخدمات التلاتة

**Authentication** → Get started → تبويب **Sign-in method**:
- **Email/Password** → Enable → Save
- **Google** → Enable → اختار إيميل الدعم → Save

**Firestore Database** → Create database:
- **Production mode** (مهم — الوضع التاني بيفتح القاعدة للكل)
- الموقع: `eur3` أو `europe-west` (أقرب لمصر)


### ٣. اعمل حسابك

**Authentication** → **Users** → **Add user**
- الإيميل وكلمة سر قوية

بعدين **انسخ الـUser UID** من الجدول (سلسلة حروف وأرقام طولها ٢٨ حرف).

### ٤. سجّل الموقع

**Project settings** (الترس) → تحت **Your apps** → أيقونة الويب `</>`
- الاسم: `elawaady-db`
- **متفعّلش** Firebase Hosting

هيطلعلك كود فيه `firebaseConfig`. **انسخه.**

### ٥. ابعتلي الـconfig

```
الـ config كامل (٦ سطور)
```

الـ**UID** وصلني وهو متحطوط خلاص في التلات ملفات:

| الملف | مكانه |
|---|---|
| `firebase-config.js` | `window.OWNER_UID` |
| `firestore.rules` | `ownerUid()` |
| `storage.rules` | `ownerUid()` |

> الـUID مش سر — هو معرّف حساب، ومعرفته لوحدها مبتديش أي صلاحية. اللي
> بيدي الصلاحية هو إنك تكون داخل بالحساب ده فعلًا، وده بيتحقق من فايربيز.

فاضل الـconfig بس عشان الكود يوصل لفايربيز. **بس ده مش معناه إن الموقع بقى
جاهز للإطلاق** — القائمة اللي تحت هي اللي بتحدد ده.

## المرحلة التانية — نشر قواعد الأمان

**دي أهم خطوة في المشروع كله.** من غيرها قاعدة البيانات مفتوحة.

بعد ما أرفع القواعد بالـUID بتاعك:

**Firestore Database** → تبويب **Rules** → امسح اللي موجود → الصق محتوى `firestore.rules` → **Publish**

**Storage** مش مستخدم خالص. لو فعّلته أصلاً، الصق `storage.rules` فيه —
الملف بيقفل كل المسارات ما عدا مجلد المالك.

### اختبار القواعد نفسها — مش الواجهة

إخفاء زرار من الواجهة مش حماية. الاختبار ده بيضرب على القواعد مباشرة من
غير ما يعدي على أي كود في `app.html` — زي بالظبط لو حد فتح الكونسول وكتب
الطلب بإيده.

```bash
cd tests/rules
npm init -y
npm i firebase-tools @firebase/rules-unit-testing firebase
cp ../../firestore.rules ../../storage.rules .
npx firebase emulators:exec --only firestore,storage \
    --project elawaady-rules-test "node rules.test.mjs"
```

(محتاج Java عشان المحاكي.) الاختبار فيه **٩٨ حالة** بتغطي:

| المجموعة | بيتأكد من إيه |
|---|---|
| ملفات المستخدمين | ما ينفعش يسجّل بدور admin أو owner، ولا يرقّي نفسه أو غيره، ولا يغيّر status، ولا يقرا ملف حد تاني |
| إنشاء التقييمات | `uid` لازم يكون بتاعه، و`status` لازم `pending`، و`featured` لازم `false`، ومفيش `moderatedBy`/`moderatedAt`، وأي حقل زيادة بيترفض |
| قراءة التقييمات | المعلّق ما يظهرش لزائر ولا لمستخدم تاني — لا نص ولا صور |
| تعديل التقييمات | صاحبه ما يقدرش يعتمده ولا يميّزه ولا يغيّر `uid`، وبعد الاعتماد ما يقدرش يعدّله ولا يمسحه |
| الروابط | القراءة عامة، والكتابة للمالك بس، و`javascript:` بيترفض حتى منه |
| صور الإثبات | الحقول السبعة بس، ورابط https بس، وأنواع الصور بس (فيديو وSVG بيترفضوا)، والصورة مربوطة بصاحب التقييم، وما تظهرش قبل الاعتماد |
| الرفض الافتراضي | أي مجموعة مش مكتوبة في القواعد مرفوضة — حتى على المالك |
| Storage | مقفول بالكامل — أي رفع بيترفض ما عدا مجلد المالك |

**نتيجة آخر تشغيل: ٩٨ من ٩٨.**

### وبعدين اتأكد من الواجهة كمان

افتح الموقع في نافذة تصفح خفي (من غير تسجيل دخول) وجرّب:

## المرحلة التالتة — الرفع على Hostinger

> **الريبو يفضل عام و GitHub Pages تفضل شغالة طول المراحل اللي فاتت.** الموقع الحالي هو اللي شغّال دلوقتي، ومحدش يقرّب لتغيير الـvisibility ولا يوقف Pages غير في الخطوة ٦ تحت — يعني بعد ما النسخة الجديدة تترفع على هوستنجر وتتجرّب وتشتغل فعلًا.

hPanel → **Websites** → `elawaady-db.com` → **File Manager** → مجلد `public_html`

### ١. باك أب الأول

لو فيه أي حاجة في `public_html`: Select All → **Compress** → انقل الـZIP **بره** المجلد.

### ٢. ارفع الملفات

هجهزلك ملف ZIP فيه الموقع جاهز. ارفعه في `public_html` واعمل **Extract**.

المفروض يبقى الشكل كده:

```
public_html/
  index.html
  login.html
  account.html
  reviews.html
  admin/
  lib/
  assets/
  firebase-config.js
  ...
```

`index.html` لازم يكون في جذر `public_html` مباشرة، مش جوه مجلد.

### ٣. الدومين والـSSL

الدومين متسجل في هوستنجر، فالربط تلقائي. اتأكد بس:

**Security** → **SSL** → لو مش مفعّل اضغط **Install SSL** → وبعدين فعّل **Force HTTPS**

### ٤. رجّع الـDNS لهوستنجر

دلوقتي بس — مش قبل كده. الـDNS حاليًا مأشّر على GitHub، ولازم يرجع لهوستنجر.

hPanel → **Domains** → `elawaady-db.com` → **DNS**

امسح الأربع A records بتوع GitHub (`185.199.108-111.153`) وحط A record واحد على IP هوستنجر (هتلاقيه في صفحة الاستضافة).

**سجلات MX متتلمسش.**

### ٥. اربط الدومين في Firebase

**Authentication** → **Settings** → **Authorized domains** → **Add domain** → `elawaady-db.com`

من غير الخطوة دي تسجيل الدخول هيترفض على الدومين.

### ٦. آخر خطوة — اقفل GitHub Pages وخلّي الريبو خاص

**دي آخر حاجة خالص، وبعد ما تتأكد إن الموقع على هوستنجر شغّال تمام** — الدخول والتقييمات ورفع الصور واللوحة.

[Settings → General](https://github.com/uncleelawaady/elawaady-portfolio/settings) → انزل تحت خالص → **Change repository visibility** → **Make private**

> أول ما الريبو يبقى خاص **GitHub Pages بتقف تلقائيًا**. عشان كده الترتيب ده مهم: هوستنجر يشتغل الأول، وبعدين نقفل التاني. لو عكست الترتيب الموقع هيقع في النص.

لو لأي سبب النسخة الجديدة اتعطلت بعد كده، رجّع الـvisibility لـPublic والـDNS لـGitHub والموقع القديم يرجع زي ما هو.

## نقاط أمان — اقراها

**١. متحطش أي مفتاح خاص في الريبو.**
الـconfig اللي هتبعتهولي عام وآمن ومعمول عشان يكون في المتصفح. اللي ممنوع خالص: **Service Account JSON** أو أي **Admin SDK credentials** — دول لو اتسربوا حد بياخد قاعدة البيانات كلها.

**٢. التوكن القديم بتاع Hostinger لسه مكشوف.**
في ريبو `30lazma` العام، ملف `.claude/settings.json` فيه Hostinger API token مكتوب صريح، وموجود في تاريخ الجيت كمان. اعمله **Revoke** من hPanel → API. مش متعلق بالمشروع ده بس لازم يتقفل.

**٣. صلاحية الأدمن مربوطة بالـUID.**
مفيش تسجيل أدمن، ومفيش زرار يعمل أدمن، ومفيش قائمة أدمن. مالك واحد بس، ومكتوب في القواعد على السيرفر. لو احتجت تغيّره بعدين بيتغير من القواعد وبس.
